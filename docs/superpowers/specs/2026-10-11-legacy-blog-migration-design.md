## 5. 주소(slug) 규칙

- **레거시 글**
  - 제목에서 특수문자 `[ ] ( ) / ? # & % , . ! ' " : < >`를 지운다.
  - 공백은 `-`로 바꾸고, 연속된 `-`는 하나로 합친다. 영문은 소문자로 바꾼다.
  - 예: `[Java] Mockito 사용법(기본)` → `java-mockito-사용법-기본`
- **기존 글 29개의 slug는 바꾸지 않는다.**
- slug가 겹치면 뒤에 `-2`, `-3`을 붙인다.
- 이관 스크립트는 `옛 주소 → 새 주소` 대응표(`scripts/migrate-legacy/url-map.json`)를 만든다. 이 표는 6.6절의 canonical 처리와 7절의 댓글 이전에 쓴다.

## 6. 본문 변환

### 6.1 방식

- 노션 **공식 API**(`@notionhq/client`)로 페이지를 만든다.
  - 지금 블로그가 읽기에 쓰는 비공식 API는 쓰기에 쓰지 않는다.
- 마크다운 → 노션 블록 변환에는 `@tryfabric/martian`을 쓴다. 그 결과를 아래 규칙에 맞게 후처리한다.
- 스크립트 위치: `scripts/migrate-legacy/` (이 레포, TypeScript, `tsx`로 실행)

  - 블로그 DB 페이지를 그 Integration에 공유한다.

### 6.3 이미지

- 로컬 이미지 465개와 원격 이미지(imgur 315개 + 기타 약 11개)를 모두 노션 **File Upload API**로 올려 image 블록에 붙인다.
  - 로컬 이미지는 모두 5MB 이하라서 무료 플랜 제한에 걸리지 않는다.
  - 원격 이미지는 내려받은 뒤 같은 방식으로 업로드한다.
- 파일을 찾지 못하거나 내려받기에 실패하면 그 자리에 `[이미지 누락: …]` 문단을 넣고, 실패 보고서에 기록한다. 공개 전환 전에 0건이 되어야 한다.
- 업로드는 캐시하지 않는다.
  - 업로드한 파일은 1시간 안에 블록에 붙여야 하고, 같은 업로드를 여러 번 붙일 수 있는지 보장되지 않기 때문이다.
  - 페이지를 다시 만들 때는 이미지도 다시 올린다.

### 6.4 요청 제한과 재실행

- 노션 공식 API의 평균 제한(초당 3회)을 지키도록 요청 큐를 둔다. 429 응답은 `Retry-After`만큼 기다렸다가 다시 시도한다.
- **멱등성**
  - 레거시 경로를 키로 해서 만든 노션 페이지 ID를 `.cache/pages.json`에 기록한다.
  - 다시 실행하면 이미 만든 페이지는 건너뛴다. `--force <경로>`를 주면 그 페이지의 본문을 지우고 다시 만든다.
- **블록 수 제한**
  - 블록 100개 단위로 나눠서 추가한다.

### 6.5 실행 단계

0. **사전 수정**
   - 지금 사이트맵은 status를 거르지 않아서, 비공개 글도 사이트맵에 들어간다.
   - 사이트맵이 `Public` 글만 넣도록 먼저 고친다.
1. **시범 이관(1~2개)**
   - status = **PublicOnDetail**로 올린다. 목록에는 나오지 않지만 slug 주소로는 열 수 있는 상태다.
     - `Private`는 상세 페이지도 열리지 않아서, 렌더링을 확인할 수 없다.
   - 로컬 dev 서버와 배포 사이트 양쪽에서 slug 주소로 직접 열어 확인한다.
   - 시범 대상
     - `[DB] Transaction과 Spring Transaction`: imgur 이미지, 표, 인용, HTML, h1, 중첩 목록, 긴 코드
     - `[기술부채] 우테코 5기 레벨2 - 3주차`: 로컬 이미지, 표, 시리즈
   - 수식이나 mermaid가 있는 글은 2차 시범에서 한 개를 더 올려 확인한다.
2. **튜닝**
   - 깨지는 부분을 변환 규칙이나 렌더러 스타일에서 고치고, `--force`로 다시 올려 확인한다.
3. **일괄 이관**
   - 사용자가 시범 결과를 승인하면 나머지 글을 옮긴다. 처음에는 status = PublicOnDetail로 올린다.
4. **공개 전환**
   - 무작위 표본 검수가 끝나면 status를 Public으로 일괄 변경한다.

### 6.6 레거시 블로그 처리 (amaran-th.github.io 레포)

## 8. 목록, 페이지네이션, 필터

### 8.1 주소

| 주소 | 내용 |
|---|---|
| `/`, `/page/[n]` | 전체 글 최신순, 페이지당 12개 |
| `/category/[category]`, `/category/[category]/page/[n]` | 카테고리별 |
| `/tag/[tag]`, `/tag/[tag]/page/[n]` | 태그별 |

- 주소에 쓰는 카테고리 값은 이모지를 뺀 이름이다(예: `/category/개발`).
- `/page/1`은 `/`로 리다이렉트한다.
- 모든 목록 페이지는 `getStaticProps` + ISR로 만들고, 그 페이지에 보여줄 글의 카드 정보만 props로 넘긴다.
- 페이지마다 canonical은 자기 자신을 가리킨다. 2페이지 이상은 title에 `- N페이지`를 붙인다.
- 사이트맵에 카테고리·태그 첫 페이지를 넣는다.

### 8.2 검색

- 검색어를 처음 입력할 때 `/api/search-index`(제목, 요약, 태그, slug만 담은 JSON, CDN 캐시)를 불러와 브라우저에서 거른다.
- 검색 결과는 페이지를 나누지 않고 한 화면에 보여준다.

### 8.3 지금 기능 정리

- `order` 정렬 옵션을 없앤다.
- 기존 `/?category=…`, `/?tag=…` 주소는 새 주소로 리다이렉트한다(`next.config.js`의 `redirects`, 쿼리 매칭 사용).
- 목록 UI(카테고리 선택, 태그 목록)는 쿼리를 바꾸던 동작을 링크 이동으로 바꾼다.

### 8.4 빌드 부하

- 빌드할 때 페이지마다 `getPosts()`가 노션 전체 조회를 반복하지 않게, 한 프로세스 안에서 결과를 공유하는 캐시를 둔다.
- 230개 글을 prerender할 때 429가 몰리지 않게 하기 위해서다.

## 9. 레거시 기능 도입 (이관 이후 단계)

- **시리즈 이전 글/다음 글**: 글 하단에 같은 `series`의 이전 글과 다음 글 링크를 표시한다.
- **목차(TOC)**: 넓은 화면에서 글 오른쪽에 heading 기반 목차를 표시한다.
  - react-notion-x의 TOC 기능을 쓸 수 있는지 먼저 확인한다.
- 홈의 `OldBlogCard`는 이관이 끝나면 없애거나 문구를 바꾼다.
